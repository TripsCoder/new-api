01概述与鉴权

API 基础地址：https://aotianzz.xyz。以下路径已包含 /v1，请勿重复拼接。创建和查询请求使用 New API 令牌，不能用登录会话 Cookie 代替。

HTTP 请求头
Authorization: Bearer sk-YOUR_NEW_API_TOKEN
Content-Type: application/json

先调用 GET /v1/models 获取当前令牌可用的模型，再使用返回的模型名提交请求。

准备参考素材 URL→创建任务→保存 id 并轮询→使用结果 URL
视频接口是异步任务，不是聊天接口或 SSE 流式接口。创建成功只表示任务已受理，不表示视频已经生成。

02接口一览

方法路径用途
POST/v1/videos创建视频任务；支持 JSON 或 multipart
GET/v1/videos/{id}查询状态及结果 URL
POST / GET/v1/video/generations
/v1/video/generations/{task_id}		兼容旧版视频任务接口

将创建响应中的 id 原样用于查询。任务 ID 通常以 task_ 开头，请勿自行拼接或截断。

03请求参数

下面是当前接入约定，并非所有模型都支持全部可选字段。时长使用 seconds，画面比例使用 size，清晰度独立使用 resolution；参考素材按需填写。参数取值需符合所选模型能力。

字段类型说明
modelstring · 必填本站公开视频模型名，按令牌权限可用
promptstring · 必填非空提示词；长度、语言及内容限制以模型为准
secondsstring秒数，例如 "5"；必须符合模型时长范围
durationinteger时长字段别名，例如 5；不要与 seconds 同时设置冲突值
sizestring画面宽高比，例如 16:9。可选比例包括 16:9、9:16、1:1、4:3、3:4、21:9；具体支持范围以所选模型为准
imagesstring[]支持多图的模型可使用图片 URL 数组；一张图也可用数组；数量与是否真正使用由模型决定
image / input_referencestring单图 URL 兼容字段；不要与 images 混用以免产生覆盖或去重差异
reference_image_urlsstring[]参考图片 URL 数组别名；新接入优先使用 images
reference_videosstring[]参考视频 HTTPS URL 数组；仅限支持参考视频的模型
reference_audiosstring[]参考音频 HTTPS URL 数组；仅限支持参考音频的模型
resolutionstring独立的清晰度档位，例如 480p / 720p / 1080p；选择模型支持的值，不放入 size，不从比例推断清晰度
metadataobject结果附加信息容器；提交时不要依赖任意自定义键
size: "16:9" 只指定画面比例，不等于固定的 1280x720。同一比例可搭配模型支持的不同清晰度；最终像素尺寸以生成文件为准。新接入直接传比例，不需要在客户端换算像素，也不要改用 ratio 字段。既有像素尺寸请求保留兼容；新示例统一使用 size + resolution。JSON 和 multipart 使用相同字段名。
seed、fps、n、generate_audio、camera_movement 等字段只在模型支持时使用。

04创建任务

示例使用 Bash 环境变量。令牌和请求应保存在你的服务端，不要把长期 API Key 写进公开网页。

cURL · 文生视频
export NEW_API_TOKEN='sk-YOUR_NEW_API_TOKEN'
curl --fail-with-body -sS 'https://aotianzz.xyz/v1/videos' \
  -H "Authorization: Bearer $NEW_API_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{
    "model": "YOUR_VIDEO_MODEL",
    "prompt": "海边日落，镜头缓慢推进，写实电影风格",
    "seconds": "5",
    "size": "16:9",
    "resolution": "720p"
  }'

创建成功返回任务对象。以下仅是结构示例，字段是否出现由模型能力决定；不要依赖示例的固定进度或时间值。

JSON · 创建响应示例
{
  "id": "task_EXAMPLE",
  "object": "video",
  "model": "YOUR_VIDEO_MODEL",
  "status": "queued",
  "progress": 0
}

立即保存 id。一次请求超时不等于创建失败：在后台任务记录中确认是否已受理，再决定是否重试，避免重复生成与扣费。

05参考图与音视频

单图、多图：推荐 JSON URL 数组

只有一张图时，images 数组保留一个元素即可。多图时保持数组顺序，不要使用重复的 JSON 键，也不要传 JSON 字符串形式的数组。

JSON · 多参考图
{
  "model": "YOUR_MULTI_IMAGE_VIDEO_MODEL",
  "prompt": "参考两张图片的场景和主体，生成自然连贯的镜头",
  "seconds": "5",
  "size": "16:9",
  "resolution": "720p",
  "images": [
    "https://your-media.example/first.jpg",
    "https://your-media.example/second.png"
  ]
}

参考视频、参考音频：仅用于具备该能力的模型

JSON · 多模态参考
{
  "model": "YOUR_MULTIMODAL_VIDEO_MODEL",
  "prompt": "根据参考图片、视频动作和音频节奏生成短片",
  "seconds": "5",
  "size": "16:9",
  "resolution": "720p",
  "images": ["https://your-media.example/subject.jpg"],
  "reference_videos": ["https://your-media.example/motion.mp4"],
  "reference_audios": ["https://your-media.example/rhythm.mp3"]
}

reference_videos 和 reference_audios 是参考素材，不表示一定生成带声音的视频。input_video / input_audio 是兼容字段，请按模型说明使用。

本地文件与对象存储

  1. 由你的应用将本地素材上传到对象存储，取得可匿名读取的 HTTPS 对象 URL。
  2. 把 URL 放到对应的图片、视频、音频数组中，再提交视频任务。
  3. URL 有效期应覆盖排队、下载和生成阶段；存储凭据只能放在服务端。

可以使用任意可访问的对象存储。私有存储需要可用的签名 URL；不要传控制台链接、本地路径、浏览器 blob: 地址或需要 Cookie 的下载页。签名 URL 应原样传递。

单参考图文件上传（兼容方式）

cURL · multipart/form-data
curl --fail-with-body -sS 'https://aotianzz.xyz/v1/videos' \
  -H "Authorization: Bearer $NEW_API_TOKEN" \
  -F 'model=YOUR_FILE_UPLOAD_VIDEO_MODEL' \
  -F 'prompt=让参考图中的主体自然运动' \
  -F 'seconds=5' \
  -F 'size=16:9' \
  -F 'resolution=720p' \
  -F 'input_reference=@./reference.png;type=image/png'
不要手动设置 multipart 的 Content-Type，交给 cURL / FormData 自动生成 boundary。每个模型对参考素材的数量和类型有自己的限制，请以 GET /v1/models 返回的信息和实际错误提示为准。

06模型差异与限制

下面描述本站当前参考媒体适配方式，不代表某个系列的每个模型都具备全部能力。公开模型名、可见性与价格以你的令牌和模型列表为准。

可用模型

模型名称和可用状态会按账号权限动态返回。请先调用 GET /v1/models，直接使用响应中的模型名称。

模型类型图片输入时长及其他注意事项
通用视频模型支持 images URL 数组图片数量、参考视频/音频和时长依模型而定
Seedance 系列支持图片 URL；部分模型支持视频或音频参考时长、分辨率和参考素材数量以模型实际能力为准。
其他视频模型按模型支持的字段传入图片、视频或音频 URL请以模型列表及请求错误提示为准，不要猜测未公开参数。
固定时长模型支持图片 URL 或文件上传部分模型有固定时长或文件大小限制，提交前请核对模型说明。

常用画幅包括 16:9、9:16、1:1、3:4、4:3 和 21:9。参考图片必须有可访问的 HTTPS 地址和正确 MIME 类型。

07查询与轮询

cURL · 查询任务
curl --fail-with-body -sS \
  'https://aotianzz.xyz/v1/videos/task_EXAMPLE' \
  -H "Authorization: Bearer $NEW_API_TOKEN"
状态含义处理
queued排队中保留任务 ID，继续轮询
in_progress生成中继续轮询，progress 仅作提示
processing处理中不是失败；等待结果 URL 就绪
completed完成保存响应中的 url 用于预览/下载
failed失败读取 error.message 或 fail_reason，停止该任务轮询

建议每 5–10 秒查询一次，总等待上限可设为 30 分钟或更长。客户端可将 success/succeeded 视为成功、failure/cancelled/canceled 视为终态失败；未知状态不要误判为完成。客户端超时不会取消已经创建的任务。

JSON · 完成响应示例（URL 仅为占位）
{
  "id": "task_EXAMPLE",
  "object": "video",
  "status": "completed",
  "progress": 100,
  "url": "https://video.aotianzz.xyz/videos/YYYY/MM/DD/task_EXAMPLE.mp4"
}

08获取视频

保存完成响应中的 url，原样交给播放器或下载程序。客户端不要再调用 /content 拉取文件，也不要自行拼接文件路径。

使用响应中的结果 URL 预览或下载时无需附带 New API 令牌。保存前检查最终状态码与 Content-Type，避免把 HTML/JSON 错误保存成视频。

09Python 完整示例

依赖 pip install requests。在环境变量中设置 NEW_API_TOKEN 与 NEW_API_VIDEO_MODEL，并按模型调整秒数和画幅。此示例真正执行时会创建计费任务。

Python · 创建一次，轮询结果
import os
import time
import requests

BASE = "https://aotianzz.xyz"
HEADERS = {"Authorization": "Bearer " + os.environ["NEW_API_TOKEN"]}
payload = {
    "model": os.environ["NEW_API_VIDEO_MODEL"],
    "prompt": "海边日落，镜头缓慢推进",
    "seconds": "5",  # 按模型支持的时长填写
    "size": "16:9",  # 画面比例，不换算像素尺寸
    "resolution": "720p",  # 独立清晰度，按模型能力选择
    # "images": ["https://your-media.example/reference.jpg"],
}

# 创建只发一次；超时/5xx 时先核对后台任务，避免重复创建。
response = requests.post(BASE + "/v1/videos", headers=HEADERS,
                         json=payload, timeout=(15, 180))
response.raise_for_status()
task = response.json()
task_id = task.get("id")
if not task_id:
    raise RuntimeError("创建响应缺少 id: " + str(task))
print("保存任务 ID:", task_id)

deadline = time.monotonic() + 30 * 60
while time.monotonic() < deadline:
    time.sleep(5)
    try:
        response = requests.get(BASE + "/v1/videos/" + task_id,
                                headers=HEADERS, timeout=(15, 60))
    except (requests.Timeout, requests.ConnectionError):
        continue  # 只重试查询，不重新创建
    if response.status_code in (429, 500, 502, 503, 504):
        time.sleep(10)
        continue
    response.raise_for_status()
    state = response.json()
    status = str(state.get("status", "")).lower()
    if status in ("failed", "failure", "cancelled", "canceled"):
        raise RuntimeError(str(state.get("error") or
                               state.get("fail_reason") or state))
    if status in ("completed", "success", "succeeded"):
        url = state.get("url")
        if url:
            print("视频 URL:", url)  # 原样交给播放器；不要打印令牌
            break
else:
    raise TimeoutError("本地等待超时；稍后继续查询 " + task_id)

10错误与重试

JSON · 鉴权错误示例
{
  "error": {
    "code": "",
    "message": "Invalid token (request id: EXAMPLE_REQUEST_ID)",
    "type": "new_api_error"
  }
}
HTTP常见原因建议
400模型参数、提示词、图片数量或时长不正确读取错误并修改参数，不重复同一无效请求
401 / 403令牌、权限、账户限制或访问被拒绝检查令牌、分组和素材访问权限
404任务 ID 不存在、格式不正确或路径不匹配使用创建时返回的完整 id；不要删掉 task_ 前缀
409视频暂未准备好继续查询状态，不重新生成
413 / 415文件过大或格式/MIME 不支持压缩或转换素材，核对 Content-Type
429请求频率或并发受限如有 Retry-After 则遵守；降低并发并退避
500 / 502 / 503 / 504服务或网络暂时异常查询可重试；创建失败先确认是否已受理，避免重复费用

错误响应通常为 JSON，但客户端仍应按状态码处理异常。余额与失败退款以平台用量记录和模型计费规则为准。排查时保留任务 ID、时间、HTTP 状态及 X-Oneapi-Request-Id，不要公开 API Key 或签名素材 URL。
