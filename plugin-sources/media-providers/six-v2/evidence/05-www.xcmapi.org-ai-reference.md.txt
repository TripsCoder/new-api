# 鸡出没API · 完整接入参考（供 AI 与开发者读取）

更新：2026-10-11。服务文档：https://www.xcmapi.com/docs/QuickStart.html 。

## 先读：证据范围与使用规则

这是一份公开的静态接口指南，不包含任何真实 API Key。本文基于 2026-10-11 读取的线上文档、软件官方配置资料与该页面保留的历史视频记录整理；本轮没有执行付费生成，也没有逐一登录这些客户端进行端到端验收。不要把文档更新日期当成所有模型的重新验证日期。

用户是新手。先确认软件名称、安装版本、操作系统、用途（聊天/看图/生图/视频/编程），只问尚未确定的信息。先给最短操作步骤，成功后再介绍高级选项。

真实 Key 由用户直接填写在软件的私有凭据区或本地环境变量。不要让用户把 Key 发到 AI 对话、公共链接、截图、代码仓库、日志、工作流 JSON 或前端 bundle 中。示例的占位符必须替换，不能照抄为真实模型。

读取本站 /v1/models 只能证明该 Key 能看见目录，不能证明端点、工具调用、流式、视觉或生成能力已经可用。先验证最小请求。图片/视频有费用，先取得用户对模型、参数和费用的确认。不要自行创建多个任务“试错”。

## 1. 地址、鉴权与协议速查

站点与教程的域名不等于所有客户端应填的 API 地址。推荐 API Origin 是 https://xcmapi.org ，OpenAI SDK/兼容客户端 Base URL 是 https://xcmapi.org/v1 。HTTP 节点填写完整端点；会自动追加版本前缀的客户端应按其字段语义填写 Origin。最终路径不能含 /v1/v1。

| 用途 | 方法与路径 | 鉴权 | 关键点 |
| --- | --- | --- | --- |
| 模型目录 | GET /v1/models | Authorization: Bearer KEY | 权限目录，不是价格或能力验收 API |
| 聊天与看图 | POST /v1/chat/completions | Bearer | messages；普通结果 choices[].message.content |
| Responses | POST /v1/responses | Bearer | input；返回 output；事件格式不同于聊天 |
| Anthropic 原生 | POST /v1/messages | Bearer；anthropic-version: 2023-06-01 | max_tokens 必填；不是 OpenAI 请求体 |
| Gemini 原生 | POST /v1beta/models/{MODEL_ID}:generateContent | x-goog-api-key | contents 与 parts；不能混用 OpenAI messages |
| 生图 | POST /v1/images/generations | Bearer | model/prompt；可选尺寸数量受型号限制 |
| 改图 | POST /v1/images/edits | Bearer | multipart 文件上传；image[] |
| 创建视频 | POST /v1/videos 或 /v1/videos/generations | Bearer | 一次创建；H3 与混合型号参数不同 |
| 查询视频 | GET /v1/videos/{task_id} | 与创建相同的 Bearer Key | 有限轮询，不再 POST |
| 下载视频 | GET /v1/videos/{task_id}/content | 首次同源请求用 Bearer | 外部跳转目标不得携带本站 Key |

## 2. 从零接入的决策流程

1. 用户先在本站令牌管理创建 Key 并选择所需分组；AI 不索要真实 Key。
2. 确认目标软件的协议。聊天 GUI 常用 OpenAI Chat Completions；Codex 用 Responses；Claude Code 用 Messages；Gemini CLI 用 Gemini 原生。
3. 按软件字段选择根地址、带 /v1 的基础地址或完整 HTTP URL，不能一律填写同一值。
4. 用户在私有界面填 Key，AI 帮用户从自己的目录中选完整模型 ID；保留后缀与大小写。
5. 先执行“只回复 OK”并检查实际文本响应；编程助手再单独测试一次工具调用。
6. 图片/视频先确认数量、时长、分辨率、费用；只发一次创建请求，保存结果或任务 ID。
7. 保存去敏配置和验证结果（软件版本、模型 ID、方法/路径、HTTP 状态、时间、请求/任务 ID），不保存 Key。

## 3. 可复制的最小请求

下列 curl 采用 Bash 语法，Key 从 XCM_API_KEY 环境变量读取。Windows PowerShell 使用后文现行文档中的对应示例，不要直接粘贴 Bash 续行符。


```bash
curl "https://xcmapi.org/v1/chat/completions" \
  -H "Authorization: Bearer $XCM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"<TEXT_MODEL_ID>","messages":[{"role":"user","content":"只回复 OK"}],"stream":false}'
```

图片理解请求体（仍提交到 /v1/chat/completions）：

```json
{
  "model": "<VISION_MODEL_ID>",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "请描述这张图片。"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "<PUBLIC_IMAGE_URL_OR_DATA_URL>"
          }
        }
      ]
    }
  ]
}
```



```bash
curl "https://xcmapi.org/v1/images/generations" \
  -H "Authorization: Bearer $XCM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"<IMAGE_MODEL_ID>","prompt":"一只橘猫坐在窗台上，柔和自然光","size":"1024x1024","n":1}'
```

Responses 的最小 JSON：

```json
{
  "model": "<RESPONSES_MODEL_ID>",
  "input": "只回复 OK"
}
```

Anthropic Messages 的最小 JSON：

```json
{
  "model": "<ANTHROPIC_MODEL_ID>",
  "max_tokens": 128,
  "messages": [
    {
      "role": "user",
      "content": "只回复 OK"
    }
  ]
}
```

Gemini generateContent 的最小 JSON：

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        {
          "text": "只回复 OK"
        }
      ]
    }
  ]
}
```

下面的“官方资料已核对”只表示配置方式有文档依据，不代表本站模型在该软件中全部实测通过。带“版本核验”的条目必须核对实际安装版本，不能保证专有功能。

### Codex

用途：OpenAI 编程助手。

入口：CC Switch → 左侧 Codex → 添加供应商 → 自定义。

协议：OpenAI Responses。

填写地址：https://xcmapi.org/v1 。

1. 找到 Codex 的配置入口：先安装并打开 Codex 与 CC Switch。在 CC Switch 左侧选 Codex，再点右上角「添加供应商」。不要在 Claude Code 页填 Codex 配置。
2. 按对照填写 3 项：供应商名称可写「鸡出没API」。基础地址填写下面的地址，Key 填你在本站创建的私有 Key。模型填写当前 Key 支持 Responses 和工具调用的完整 ID。
3. 启用后重新打开 Codex：保存供应商并启用。彻底退出旧 Codex 窗口或终端，再从相同环境重新打开。在一个空的测试文件夹里开始对话。
4. 发第一条消息：发送「只回复 OK，不修改文件，不运行命令」。收到文字后，再单独测试读取测试文件。只显示模型名称不算成功。

限制与验收：本页配置面向 Codex CLI 及读取该配置的客户端。桌面产品与组织策略会随版本变化，以安装版本的自定义服务商入口为准。；官方当前配置参考仅列出 wire_api=responses；聊天接口能用不能证明 Codex 可用。；截图是官方软件界面参考；本轮未用真实 Key 完成 Codex 调用。

来源：https://learn.chatgpt.com/docs/config-file/config-reference

4. 检查连接并发送消息：先输入 /status，核对 Anthropic base URL 指向本站且鉴权方式正确；再发「只回复 OK，不修改文件，不运行命令」。

限制与验收：本页以 Claude Code 的网关能力为准，不将 Claude 网页聊天当作相同入口。；图中是官方演示，不能当作本站 API 已调用成功的证据。；本轮未实机验证客户端各版本的网关兼容性。

### Hermes Agent

用途：开源智能体。

入口：已安装 Hermes 时，先退出正在进行的聊天，在终端运行 hermes model → Custom endpoint (self-hosted / VLLM / etc.)。Web UI 的 Models → Change 用于选择已经配置好的提供商。。

协议：本指南采用 OpenAI Chat Completions。官方自定义端点说明要求服务实现 /v1/chat/completions；不要把其他协议直接填进这一方案。。

填写地址：https://xcmapi.org/v1 。

1. 打开自定义端点向导：在运行 Hermes 的终端退出当前会话，执行 hermes model，选择 Custom endpoint。聊天内 /model 仅切换已有配置，不能替代新建提供商。
2. 填入地址和自己的密钥：基础 URL 填本站 /v1 地址。API Key 在自己的机器上填写，不发给别人。Hermes 官方默认示例支持在配置中引用环境变量，推荐把密钥与普通配置分开。
3. 选择准确模型并保存：Model name 填 API 控制台实际提供的模型 ID；向导保存到 Hermes 的 config.yaml。若使用图中的 Web UI，在提供商列表选已配置来源，再选模型并点 Switch；该操作对新会话生效。
4. 新建会话发一句测试：重新开始会话，确认当前模型后发送“只回复：连接成功。不要调用工具、不要读取文件。”。能回复只证明基础文本通道可用；工具、图片和长上下文仍需分别验证。

限制与验收：Hermes 截图展示官方模型选择器，原图左下角可见 v0.11.0；图片不是当前已安装版本证明，也不是自定义 URL/API Key 表单。；官方仓库固定提交提供可追溯证据，不等于每位用户安装的稳定版具有相同界面。；本轮未运行 Hermes、未验证本站模型、流式输出、工具调用或辅助模型路由。；辅助模型可能有独立的路由/密钥需求；主模型连接成功并不意味着辅助能力均可用。

来源：https://hermes-agent.nousresearch.com/docs/integrations/providers

4. 保存并在对话中选中测试：点击保存，回到对话的模型选择器选新建模型，再发送“只回复：连接成功。不要调用工具、不要读取文件。”。先核对文本回复，再单独验收文件/工具等功能。

入口：已经运行的 Web UI → 设置 → 模型 → 添加模型提供商 → 自定义模型 API。官方 README 启动命令为 npx @deepseek-ai/dsh web，默认本机页面 http://127.0.0.1:3080；本轮没有执行安装或启动。。

协议：自定义模型 API 可选 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages；分别写为 openai-completions、openai-responses、anthropic-messages。同一提供商只选一种协议。。

填写地址：https://xcmapi.org/v1 。

3. 选协议、填密钥并添加模型：此入门方案选择 OpenAI Chat Completions，填写本站 API Key。点击添加模型并手动填写可用模型 ID；“获取可用模型”是可选网络探测，不是接入保证。网关支持其他协议时，可另外新建提供商并选择相应协议。

## 7. 图片与视频流程约束

### 图像

- 看图：支持视觉的聊天模型，messages[].content 使用 text + image_url。远程 URL 必须可被服务端访问；本机路径不是 URL。
- 生图：Images generation，模型必须支持该端点；不对所有型号假定相同 size/n/返回格式。
- 改图：Images edit，上传文件；不要手动构造 multipart 边界。
- 返回 data[].url 时读取临时资源；返回 data[].b64_json 时在本地解码，不要把它当 URL。
- Gemini 原生图像能力按 Gemini 请求与响应结构处理，不能把生成模型硬塞进 OpenAI Images。

### 视频

1. 验证模型权限、对应参数和费用。H3 用 aspect_ratio；混合型号按配置用 ratio。
2. 为一次业务生成只发一个 POST，记录 task_id 和发起时间。POST 超时或结果不确定时先核查，不自动重新创建；不假定支持 Idempotency-Key。
3. 解析顶层或 data 中的 id / task_id / request_id，统一保存为任务 ID。
4. 使用同一 Key，每 3–5 秒 GET 查询；设置最大次数、总超时和指数退避上限。遇到 Retry-After 按它等待。
5. pending/queued/in_progress 继续等；done/completed/succeeded/success 取视频；failed/error/expired/cancelled/canceled 停止并记录。
6. 未知状态或轮询超时保留 ID 并转人工，不能当作失败重新 POST。
7. 下载 /content 时只给本站请求加 Authorization；外部 30x 或 video_url 请求不带 Key，禁止 curl --location-trusted。
8. 播放或解析文件验证实际时长/尺寸/编码，再认定生成成功。停止轮询不等于取消任务；没有文档依据不要调用 DELETE。

### n8n 节点连接

手动触发 → HTTP Request（POST 创建，Retry On Fail 关闭）→ 提取并持久化 task_id → Wait 5 秒 → HTTP Request（GET 查询）→ If/Switch。完成分支下载，失败分支停止，运行中回到 Wait。不要连回创建节点。循环增加计数与开始时间，超出阈值停止自动轮询。Header Auth 凭据：Name=Authorization，Value=Bearer 加空格加私有 Key。工作流导出时移除凭据值。

## 8. 新手错误处理与验收

| 现象 | 先检查 | 避免 |
| --- | --- | --- |
| 401 | Key 是否为空、带空格、停用、过期 | 重复粘贴到公开对话 |
| 403 | 分组、模型权限与接口权限 | 自动换未知模型 |
| 404 | Origin/Base/完整 URL 与实际协议；是否 /v1/v1 | 盲目添加更多版本路径 |
| 400 / 422 | 模型名与最小参数；类型/尺寸/时长是否支持 | 反复创建视频试参数 |
| 429 | 余额、配额与速率错误正文；Retry-After | 无上限重试 |
| 5xx / 网络超时 | 请求是否已被接受；视频查记录 | 自动再次 POST 视频 |
| 有目录没有回复 | 真正端点、模型能力、客户端日志中的请求路径 | 把连通性当成功 |
| CORS | 将业务 Key 留在服务端，由自己的后端调用 | 把私有 Key 写入公共前端 |
| 工具调用失败 | 模型与适配器是否支持、返回格式是否正确 | 只测试聊天就宣布 Agent 可用 |

验收至少记录：目标软件与版本、模型 ID、实际协议和路径、最小文本结果；需要视觉时记录具体图像描述；需要生成时记录一次受控生成结果；视频记录创建、查询、下载、可播放全过程。不要记录 Key 或签名下载地址。

## 鉴权与 Base URL

先确认接口地址和 KEY，再验证分组权限。

1. 在[API 密钥](https://www.xcmapi.com/keys)页创建 KEY，选择对应的文本、图片或视频分组。
2. 把 KEY 存在服务端环境变量 `XCM_API_KEY`；不要把它嵌进网页 JavaScript 或移动端安装包。
3. 用同一 KEY 请求模型目录；使用返回的完整模型 ID。

| 配置项 | 填写内容 | 适用方式 |
| --- | --- | --- |
| Origin | `https://xcmapi.org` | 直接拼接完整路径，如 /v1/models |
| Base URL | `https://xcmapi.org/v1` | OpenAI 兼容 SDK，SDK 会追加 /responses 等路径 |
| 鉴权 | `Authorization: Bearer $XCM_API_KEY` | OpenAI 风格接口；Gemini 见原生协议章节 |
| 请求类型 | `Content-Type: application/json` | JSON 请求；上传文件时采用对应 multipart 格式 |

```
export XCM_API_KEY="<YOUR_API_KEY>"

export XCM_MODEL="<MODEL_ID>"

export XCM_API_ORIGIN="https://xcmapi.org"
```

```
$env:XCM_API_KEY = "<YOUR_API_KEY>"

$env:XCM_MODEL = "<MODEL_ID>"

$env:XCM_API_ORIGIN = "https://xcmapi.org"
```

常见地址错误 

不要拼成 `/v1/v1/responses`，也不要把完整 `/v1/chat/completions` 当 SDK Base URL。遇到 401 先检查 KEY；404 先核对路径、模型 ID 与分组。

## 创建和管理 KEY

KEY 与分组权限一起决定可调用模型。

1 

访问 [鸡出没API 控制台](https://www.xcmapi.com/) 并登录。

2

## 文本 API

Chat Completions 与 Responses 是两套请求结构，按你的客户端协议选择。

| 接口 | 请求内容 | 输出位置 |
| --- | --- | --- |
| POST /v1/chat/completions | messages 数组 | choices[].message / delta |
| POST /v1/responses | input 字符串或消息 / 工具项 | output 数组或 Responses SSE 事件 |

```
curl "https://xcmapi.org/v1/chat/completions" \
  -H "Authorization: Bearer <YOUR_API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{

    "model": "<MODEL_ID>",

    "messages": [{"role": "user", "content": "Hello"}],

    "stream": false

  }'
```

```
curl "https://xcmapi.org/v1/responses" \
  -H "Authorization: Bearer <YOUR_API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{

    "model": "<MODEL_ID>",

    "input": "Hello"

  }'
```

不要混用字段 

Chat Completions 使用 `messages`；Responses 使用 `input`。视频创建请求请使用视频章节中的专用路径。

```
import json, os, urllib.request

origin = os.environ.get("XCM_API_ORIGIN", "https://xcmapi.org").rstrip("/")

payload = {"model": os.environ["XCM_MODEL"], "input": "Reply OK", "stream": False}

request = urllib.request.Request(origin + "/v1/responses",

    data=json.dumps(payload).encode(), method="POST",

    headers={"Authorization": "Bearer " + os.environ["XCM_API_KEY"],

             "Content-Type": "application/json"})

with urllib.request.urlopen(request, timeout=90) as response:

    result = json.load(response)

for item in result.get("output", []):

    if item.get("type") == "message":

        for content in item.get("content", []):

            if content.get("type") == "output_text":

                print(content["text"])
```

## 流式响应与工具结果

按完整 SSE 事件处理增量数据，并把工具结果与对应 call_id 配对。

POST /v1/responses stream: true 

```
curl -N --fail-with-body --max-time 120 "$XCM_API_ORIGIN/v1/responses"   -H "Authorization: Bearer $XCM_API_KEY"   -H "Content-Type: application/json"   -d '{"model":"<MODEL_ID>","input":"Reply OK","stream":true}'
```

| 处理阶段 | 客户端动作 |
| --- | --- |
| 分片到达 | TCP 数据块不等于完整 JSON；按空行分割 SSE，合并同一事件的数据行后解析 |
| 文本增量 | Chat 使用 choices[].delta；Responses 使用 response.output_text.delta |
| 工具调用 | 收齐工具参数，再执行本地工具；保留完整工具项与 call_id |
| 回传结果 | function_call 对应 function_call_output；custom_tool_call 对应 custom_tool_call_output |
| 终态 | 检查完成、失败或不完整状态；HTTP 200 或连接关闭都不能单独证明任务成功 |

```
{

  "model": "<MODEL_ID>",

  "input": [

    {"role": "user", "content": "查询测试数据"},

    {"type":"function_call","call_id":"call_example","name":"lookup","arguments":"{\"id\":1}"},

    {"type":"function_call_output","call_id":"call_example","output":"{\"result\":\"ok\"}"}

  ]

}
```

保留会话上下文 

生产客户端应保留完整的已返回 output 项（包括需要续传的推理项）、原始 tools 定义及调用 ID。并行工具要逐个回传结果。不要在连接中断后自动重新执行有写入副作用的工具。`previous_response_id` 与服务端状态保存能力需按具体渠道确认。

## 原生 h3（独立协议）· 查询与下载

轮询使用创建任务时相同的 KEY；建议 3–5 秒一次，设置总次数和超时上限。

GET /v1/videos/{task_id} 

```
curl "https://xcmapi.org/v1/videos/<REQUEST_ID>" \
  -H "Authorization: Bearer <YOUR_API_KEY>"

curl -L "https://xcmapi.org/v1/videos/<REQUEST_ID>/content" \
  -H "Authorization: Bearer <YOUR_API_KEY>" \
  -o h3-output.mp4
```

| 状态 | 含义 | 处理方式 |
| --- | --- | --- |
| `pending` / `queued` | 任务已创建，等待执行 | 继续轮询，不要重复创建。 |
| `in_progress` | 正在生成 | 约 3 秒后再次查询。 |
| `done` / `completed` / `succeeded` / `success` | 生成完成 | 读取 `video.url`、`video_url`、顶层 `url`，或请求 content。 |
| `failed` / `error` | 生成失败 | 记录任务 ID 和错误信息后联系管理员。 |

下载与鉴权 

先通过本站 `/content` 入口获取结果。如返回跳转地址，外部地址不要携带本站 Authorization。不要使用 `curl --location-trusted`。下载前确认状态已完成；过期链接需核查任务状态。

重试与停止 

只对 GET 查询采用有上限的重试。关闭页面或停止轮询不等于取消任务，本站未在本页提供取消接口；不要尝试未公布的 DELETE 路径。任务失败或超时时保留 task_id 和发生时间。

## 原生 h3（独立协议）· 首尾帧与多素材

文生视频、首尾帧、多图与音频示例分开查看，不要混用不同模型的素材字段。

H3 高级能力 以下示例使用 H3 1.5 线路的公开请求字段。图片统一使用 {"url":"<IMAGE_URL>"} ；音频使用 reference_audios 中的预设 voice_id 。是否开放首尾帧、多图或音频能力，以当前 Key 的模型目录和分组权限为准。 图片地址请替换 示例里的 <IMAGE_URL_n> 只是占位符，不是本站地址。请替换成你自己的、无需登录即可访问的公网 HTTPS 图片地址；不要填写 localhost 、 127.0.0.1 、局域网 IP 或只在本机浏览器中可打开的地址。 

#### 首尾帧：固定开始和结束画面

`image` 固定首帧，`last_frame` 固定尾帧；只传 `last_frame` 也可以让模型自动生成开场并落到指定尾帧。提示词可省略，但建议用来描述两帧之间的运动。

```
curl "https://xcmapi.org/v1/videos/generations" \
  -H "Authorization: Bearer <YOUR_API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{

    "model": "h3",

    "prompt": "镜头平滑向前推进，人物从画面左侧走到右侧",

    "image": {"url": "<IMAGE_URL_FIRST>"},

    "last_frame": {"url": "<IMAGE_URL_LAST>"},

    "duration": 8,

    "aspect_ratio": "16:9",

    "resolution": "720p"

  }'
```

#### 多图参考：同时引用多个主体

把人物、服装、道具或场景分别放入 `reference_images`，并在提示词中用 `<IMAGE_1>`、`<IMAGE_2>` 等标签指代。H3 1.5 单次最多 7 张参考图，超过上限会返回 400。

```
curl "https://xcmapi.org/v1/videos/generations" \
  -H "Authorization: Bearer <YOUR_API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{

    "model": "h3",

    "prompt": "<IMAGE_1> 中的人物穿着 <IMAGE_2> 中的衣服，站在 <IMAGE_3> 的场景里，慢慢转身",

    "reference_images": [

      {"url": "<IMAGE_URL_1>"},

      {"url": "<IMAGE_URL_2>"},

      {"url": "<IMAGE_URL_3>"}

    ],

    "duration": 8,

    "aspect_ratio": "9:16",

    "resolution": "720p"

  }'
```

#### 多图多音频：多角色分别绑定声音

只创建一次，保存任务 ID。进程退出后可恢复查询，不会自动重新创建。

```
"""H3 example: POST once, persist task ID, resume polling without resubmission.

Environment: XCM_API_KEY, optionally XCM_API_ORIGIN (HTTPS origin, no /v1).

Usage: python h3_client.py --submit  OR  python h3_client.py --task-id TASK_ID

Submitting generates a billable video. Polling success is not a billing guarantee.

"""

import argparse

import json

import os

from pathlib import Path

import time

import urllib.error

import urllib.parse

import urllib.request

class NoRedirect(urllib.request.HTTPRedirectHandler):

    def redirect_request(self, req, fp, code, msg, headers, newurl):

        return None  # Never forward the API key to a redirected host.

def request(method, path, payload=None):

    origin = os.environ.get('XCM_API_ORIGIN', 'https://xcmapi.org').rstrip('/')

    parts = urllib.parse.urlsplit(origin)

    if parts.scheme != 'https' or not parts.netloc or parts.path or parts.query or parts.fragment or parts.username:

        raise ValueError('XCM_API_ORIGIN must be an HTTPS origin without /v1')

    key = os.environ['XCM_API_KEY']

    req = urllib.request.Request(origin + path, method=method,

        headers={'Authorization': 'Bearer ' + key, 'Content-Type': 'application/json'},

        data=json.dumps(payload).encode() if payload is not None else None)

    try:

        with urllib.request.build_opener(NoRedirect).open(req, timeout=30) as response:

            data = json.load(response)

            return response.status, data, None

    except urllib.error.HTTPError as error:

        retry = error.headers.get('Retry-After', '')

        retry_seconds = min(15, max(3, int(retry))) if retry.isdigit() else None

        # Do not print a raw body that might contain user content or credentials.

        return error.code, {}, retry_seconds

def unwrap(data):

    return data['data'] if isinstance(data.get('data'), dict) else data

def poll(task_id, attempts=120):

    path = '/v1/videos/' + urllib.parse.quote(task_id, safe='')

    for _ in range(attempts):

        try:

            status, response, retry = request('GET', path)

        except (TimeoutError, urllib.error.URLError):

            time.sleep(5)

            continue  # Retrying GET does not create another video.

        if status in (429, 502, 503, 504):

            time.sleep(retry or 5)

            continue

        if status != 200:

            raise RuntimeError(f'Query HTTP {status}; keep task ID and check the documentation')

        data = unwrap(response)

        state = data.get('status')

        if state in ('failed', 'error', 'cancelled', 'canceled', 'expired'):

            raise RuntimeError('Task ended without success; keep task ID for support')

        if state in ('done', 'completed', 'succeeded', 'success'):

            return data

        if state not in ('pending', 'queued', 'in_progress', 'processing', 'running'):

            raise RuntimeError('Unrecognized task status; inspect the response privately')

        time.sleep(5)

    raise TimeoutError('Polling stopped. Resume using --task-id; do not resubmit the POST')

def download(ident, path):
    """Fetch /content, following at most five HTTPS redirects/JSON links."""
    import re
    from urllib import request as http, error as errors, parse as urls
    if not isinstance(ident, str) or not re.fullmatch(r'[A-Za-z0-9][A-Za-z0-9_.:-]{0,159}', ident):
        raise ValueError('Invalid task ID')
    if not path.is_absolute():
        raise ValueError('Choose an explicit absolute output path')
    if path.exists():
        raise FileExistsError('Output exists; choose a new path')

    def checked_url(value, base=None):
        if not isinstance(value, str) or not value or any(ord(c) <= 32 or ord(c) == 127 for c in value) or '\\' in value:
            raise ValueError('Invalid download URL')
        target = urls.urljoin(base, value) if base else value
        p = urls.urlsplit(target)
        if p.scheme != 'https' or not p.hostname or p.username is not None or p.password is not None or p.fragment or p.port == 0:
            raise ValueError('Download URL must be HTTPS without credentials or fragment')
        return target, (p.hostname.lower(), p.port or 443)

    origin = os.environ.get('XCM_API_ORIGIN', 'https://xcmapi.org').rstrip('/')
    origin, auth_origin = checked_url(origin)
    parsed = urls.urlsplit(origin)
    if parsed.path or parsed.query:
        raise ValueError('Use an HTTPS origin without /v1')
    key = os.environ.get('XCM_API_KEY', '')
    if not key.strip() or '\n' in key or '\r' in key:
        raise ValueError('Set XCM_API_KEY in the server environment')
    url = origin + '/v1/videos/' + urls.quote(ident, safe='') + '/content'
    opener = http.build_opener(NoRedirect)
    send_auth = True
    hops = 0
    limit = 250 * 1024 * 1024
    part = path.with_name(path.name + '.partial')
    created = False
    try:
        while True:
            url, current_origin = checked_url(url)
            send_auth = send_auth and current_origin == auth_origin
            headers = {'Accept': 'video/mp4, application/octet-stream, application/json'}
            if send_auth:
                headers['Authorization'] = 'Bearer ' + key
            req = http.Request(url, headers=headers)
            try:
                response = opener.open(req, timeout=90)
            except errors.HTTPError as exc:
                response = exc
            with response:
                kind = response.headers.get('Content-Type', '').split(';')[0].strip().lower()
                if response.status in (301, 302, 303, 307, 308):
                    target = response.headers.get('Location')
                elif response.status != 200:
                    raise RuntimeError(f'Download HTTP {response.status}; retain task ID')
                elif kind == 'application/json' or kind.endswith('+json'):
                    raw = response.read(1024 * 1024 + 1)
                    if len(raw) > 1024 * 1024:
                        raise RuntimeError('Download JSON exceeds 1MiB')
                    try:
                        data = json.loads(raw)
                    except (ValueError, UnicodeError):
                        raise RuntimeError('Invalid download JSON') from None
                    if isinstance(data, dict) and isinstance(data.get('data'), dict):
                        data = data['data']
                    if not isinstance(data, dict):
                        raise RuntimeError('Expected a download URL object')
                    video = data.get('video')
                    results = data.get('result_urls')
                    target = (data.get('url') or data.get('download_url') or data.get('video_url') or data.get('content_url')
                              or (video.get('url') if isinstance(video, dict) else None)
                              or (results[0] if isinstance(results, list) and results else None))
                else:
                    if kind not in ('video/mp4', 'application/octet-stream'):
                        raise RuntimeError('Not an MP4 download response')
                    length = response.headers.get('Content-Length')
                    if length is not None and (not length.isdigit() or not 0 < int(length) <= limit):
                        raise RuntimeError('Invalid or excessive media length')
                    first = response.read(4096)
                    if len(first) < 12 or first[4:8] != b'ftyp':
                        raise RuntimeError('Response is not an MP4')
                    size = len(first)
                    with part.open('xb') as stream:
                        created = True
                        stream.write(first)
                        while True:
                            chunk = response.read(1024 * 1024)
                            if not chunk:
                                break
                            size += len(chunk)
                            if size > limit:
                                raise RuntimeError('Media exceeds the 250MiB client limit')
                            stream.write(chunk)
                    if length is not None and size != int(length):
                        raise RuntimeError('Incomplete media response; retain task ID')
                    break
                if hops >= 5:
                    raise RuntimeError('Too many download redirects/JSON links (maximum 5)')
                url, _ = checked_url(target, url)
                hops += 1
        # Publish exclusively: a concurrent download must not overwrite this file.
        for attempt in range(6):
            try:
                os.link(part, path)
                break
            except PermissionError:
                if attempt == 5:
                    raise
                time.sleep(.1)
        return size
    finally:
        if created:
            part.unlink(missing_ok=True)

def main():

    parser = argparse.ArgumentParser(description=__doc__)

    action = parser.add_mutually_exclusive_group(required=True)

    action.add_argument('--submit', action='store_true')

    action.add_argument('--task-id')

    parser.add_argument('--output', type=Path, default=Path.cwd() / 'h3-output.mp4')

    args = parser.parse_args()

    task_id = args.task_id

    if args.submit:

        status, response, _ = request('POST', '/v1/videos', {

            'model': 'h3', 'prompt': 'A cat walking slowly on a sunny beach',

            'duration': 6, 'resolution': '480p', 'aspect_ratio': '16:9',

        })

        if status not in (200, 201, 202):

            raise RuntimeError(f'Create HTTP {status}; do not automatically retry POST')

        data = unwrap(response)

        task_id = data.get('request_id') or data.get('id') or data.get('task_id')

        if not isinstance(task_id, str) or not task_id:

            raise RuntimeError('No task ID found; do not automatically resubmit')

        # Contains only your task ID; use a private application database in production.

        Path('h3-last-task.json').write_text(json.dumps({'task_id': task_id}), encoding='utf-8')

    import re
    if not isinstance(task_id, str) or not re.fullmatch(r'[A-Za-z0-9][A-Za-z0-9_.:-]{0,159}', task_id):
        raise ValueError('Invalid task ID; do not resubmit')

    print('Task ID:', task_id)

    poll(task_id)

    size = download(task_id, args.output)
    print('Downloaded:', args.output, 'bytes:', size)

if __name__ == '__main__':

    main()
```

### 上传文件与引用素材的区别

当前视频创建接口为 `POST /v1/videos/generations`，也支持 `POST /v1/videos`；两者要求 `Authorization: Bearer YOUR_API_KEY` 和 `Content-Type: application/json`。没有向这些视频型号提供独立的素材文件存储上传接口。流程是：用户文件 → 你自己的存储/素材服务 → 公网HTTPS URL → 视频创建JSON。

不能把本地路径、data URL、blob URL或multipart文件直接提交到视频JSON。`POST /v1/images/edits` 是图片编辑任务，不是视频素材上传仓库。不要为了上传素材而先执行图片生成/编辑。

- `images`：URL字符串或对象 `{url,name?,type?,duration_seconds?}`；普通参考图省略type。帧类型仅 `first_frame`、`end_frame`。
- `videos`：当前minimax-h3必须使用对象 `{url,duration_seconds,name?}`。
- `audios`：URL字符串或对象 `{url,name?,duration_seconds?}`；音频时长字段可选。独立数组中的video/audio对象不带type。
- `materials`：对象数组 `{type:image|video|audio,url,name?,duration_seconds?}`。H3的video项必须有duration_seconds。
- `materials` 不能与非空images/videos/audios混用。首尾帧各最多1个，尾帧必须伴随首帧；帧模式不能混入普通参考图、视频或音频。
- `duration` 是输出视频时长；`duration_seconds` 是素材本身时长，正数且最多120秒，不能当作输出时长。
- 元素不接受这些字段以外的属性；name为1到80字符。

视频适配层JSON请求体最大128KiB；这不是素材文件大小上限。二进制文件不随JSON上传。

URL必须是公网HTTPS（443），不含用户名、密码、片段或空白，长度最多8192。禁止localhost、私网IP与本地域名。可以保留签名查询参数，但有效期要覆盖素材读取和任务处理。不得把本站Key交给素材域名。适配层没有声明完整的源文件MIME/体积/分辨率上限，不可从URL后缀或宣传备注推断。

占位 `your-cdn.example.com` 可能通过URL格式校验，但不代表实际可读取。所有占位URL和业务号必须替换；错误素材转发上游后不保证免费失败。每个业务单只发送一次，原业务号重复或冲突会拒绝，不自动新建任务。

### 只提交一次：Python

```python
import json, os
from pathlib import Path
from urllib import request

payload = json.loads(Path("video-request.json").read_text(encoding="utf-8"))
serialized = json.dumps(payload, ensure_ascii=False)
if "your-cdn.example.com" in serialized or "YOUR_UNIQUE_ORDER_ID" in serialized:
    raise SystemExit("先替换素材 URL 和固定的业务请求号")

class NoRedirect(request.HTTPRedirectHandler):
    def redirect_request(self, *args, **kwargs):
        return None

req = request.Request(
    "https://xcmapi.org/v1/videos/generations",
    data=serialized.encode("utf-8"),
    headers={
        "Authorization": "Bearer " + os.environ["XCM_API_KEY"],
        "Content-Type": "application/json",
    },
    method="POST",
)
# 只发送一次。超时、422 或其他错误时保留原业务号，先核查，不自动重试。
with request.build_opener(NoRedirect()).open(req, timeout=90) as response:
    result = json.load(response)
Path("video-create-response.json").write_text(
    json.dumps(result, ensure_ascii=False), encoding="utf-8"
)
print(result.get("task_id") or result.get("id") or result.get("request_id"))
```

返回后持久化task_id/id/request_id，使用原Key进行 `GET /v1/videos/{task_id}` 查询，完成后请求 `GET /v1/videos/{task_id}/content`。创建超时或结果不明时先核查原单，不更换client_request_id重发。

### H3视频时长的已知校验边界

上游要求视频对象包含duration_seconds，但当前适配层可能放行遗漏时长的对象或单独URL字符串。本文OpenAPI和推荐请求在客户端先要求填齐；不能承诺缺字段会在本地拒绝，或上游失败不会扣费。

### 错误与停止条件

| 问题 | 适配层错误 | 处理 |
|---|---|---|
| 不支持的素材、超限、非法URL、错误元素、混用 | 400 invalid_request_error | 修正原输入；不能删除素材后假装成功 |
| 视频创建使用文件multipart | 415 unsupported_media_type | 使用JSON与公网URL |
| 缺少/无效业务号 | 422 video_request_id_required / video_request_id_invalid | 使用固定唯一的16–128位[A-Za-z0-9_.:-] |
| 同号重复/内容冲突 | 422 video_request_already_submitted / video_request_conflict | 查询原任务或人工核查，不换号重建 |

原生模型 `h3` 与本节 `minimax-h3` 是不同接入协议。原生h3的reference_images/reference_audios/aspect_ratio不能搬到本节；本节推荐ratio和images/videos/audios/materials，ratio的兼容别名不是原生协议兼容承诺。原生h3须由Key单独确认，参看 https://xcmapi.org/docs/QuickStart.html#h3-video 。

## 生产 API 对接方案

将鉴权、请求生命周期、任务恢复和计费核对放到服务端。

1. CLIENT用户请求
2. YOUR SERVER权限 / 限流 / 业务单
3. SITE API文本或视频任务
4. WORKER保存结果与账单关联

| 模块 | 实现要求 | 验收标准 |
| --- | --- | --- |
| 鉴权配置 | 以环境变量 / 密钥服务保存 KEY；按业务选择明确的分组 | 请求中仅向本站携带 KEY，错误日志脱敏 |
| 模型选择 | 按 KEY 获取 /v1/models，保存用户选择的完整模型 ID | 模型不存在时明确报错，不静默切换昂贵模型 |
| 文本转发 | 透传当前协议支持的字段；设置连接和读取超时 | JSON / SSE 各自解析，终态与业务成功分开判断 |
| 视频创建 | 先建立本地业务单；创建成功立即记录任务 ID | 重复点击只创建一次，进程重启不会自动重发 POST |
| 状态 Worker | 3–5 秒轮询，有限并发；429 依据 Retry-After 退避 | 断线后可通过 task_id 恢复，失败与过期状态终止 |
| 结果存储 | 记录返回格式与过期时间；必要时安全保存生成文件 | 不会把本站 KEY 传给外部下载 URL |
| 计费关联 | 业务单与 request_id / task_id、模型、分辨率、用量记录关联 | 调价后采用实时分组价，异常可追踪，不推测退款政策 |

建议的本地任务表 

字段：business_id（唯一）、key_config_id（非真实 KEY）、model、resolution、duration、state、task_id、created_at、last_polled_at、attempt_count、error_code。状态采用 creating → submitted → running → completed/failed/unknown；unknown 表示创建结果不确定，需要查询核实。

幂等边界 

不要假设服务端已支持任意 `Idempotency-Key` 或 webhook。先在你自己的数据库使用唯一业务单和互斥锁防重；只有渠道正式文档公布时才使用服务端幂等或回调。

#### 超时建议（客户端配置，不是服务承诺）

模型目录 30 秒；文本请求按模型设置合理的首包及读取超时；视频创建可用 60 秒、单次查询 30 秒、后台轮询最多 120 次。每次网络请求自身也有超时，因此总耗时可能高于轮询间隔之和。长期任务应由后台 Worker 承担，不依赖浏览器页面一直打开。

## 错误码与排查

先按请求阶段排查，再检查模型、分组和协议。

| 状态码 | 常见场景 | 处理方式 |
| --- | --- | --- |
| 400 | 字段、枚举、媒体组合或 JSON 不合法 | 按错误消息修正请求。 |
| 401 | Key 缺失、无效或已撤销 | 检查鉴权头和 Key。 |
| 402 | 余额、订阅或额度不足 | 检查账户余额和分组额度。 |
| 403 | 分组未开启对应能力 | 更换有权限的 Key 或联系管理员。 |
| 404 | 模型、任务或接口不存在 | 检查模型目录、任务 ID 和路径。 |
| 429 | 频率或并发受限 | 降低并发并稍后重试。 |
| 502/503 | 渠道不可用或暂无可调度账号 | 稍后重试；持续出现时联系售后。 |

排查顺序 

1. GET /v1/models 验证鉴权 → 2. 检查 KEY 分组 → 3. 核对完整路径 → 4. 最小请求体 → 5. 检查任务 ID / 请求 ID → 6. 联系客服时提供时间、模型、状态码和脱敏错误。

| 现象 | 优先检查 |
| --- | --- |
| 200 但没有内容 | 响应终态是否 failed/incomplete，SSE 是否有 error 事件 |
| 工具调用后续接失败 | call_id 是否匹配、工具结果类型是否正确、前次 output 是否完整 |
| 视频参数 400 | duration/resolution 范围、素材数量、首尾帧和音频是否混用 |
| 视频接口 404 | 该分组是否支持视频路径；内测混合分组目前暂未开放 |
| 任务已完成但下载失败 | 结果 URL 是否过期、是否使用正确 KEY / 任务归属、content 是否可用 |

联系支持 

保留必要的请求 ID、任务 ID、时间和客户端版本；完整 KEY、Cookie、用户提示词和私密素材地址不必公开。

## 11. API 软件连接目录：七款软件的完整步骤

资料核对日期：2026-10-11。真实界面参考不等于本站端到端调用成功。URL 的 /v1 规则取决于软件字段，以下逐项说明。

### Codex

软件身份 / 官网：https://developers.openai.com/codex

配置文档：https://learn.chatgpt.com/docs/config-file/config-reference

协议：OpenAI Responses

Base URL：https://xcmapi.org/v1

入口：CC Switch → 左侧 Codex → 添加供应商 → 自定义

1. 找到 Codex 的配置入口：先安装并打开 Codex 与 CC Switch。在 CC Switch 左侧选 Codex，再点右上角「添加供应商」。不要在 Claude Code 页填 Codex 配置。

   - 基础地址 Base URL：https://xcmapi.org/v1
   - API Key：在软件私有输入框中粘贴自己的 Key
   - 模型 ID：从当前 Key 的模型目录复制完整 ID
3. 启用后重新打开 Codex：保存供应商并启用。彻底退出旧 Codex 窗口或终端，再从相同环境重新打开。在一个空的测试文件夹里开始对话。
4. 发第一条消息：发送「只回复 OK，不修改文件，不运行命令」。收到文字后，再单独测试读取测试文件。只显示模型名称不算成功。

成功标准（供用户后续验证）：新对话实际返回 OK；接入方用量记录能找到这次请求。若要编程，继续单独验证一次文件读取或工具调用。

排错：

## 第一次导入与凭据设置

1. 在 n8n 新建空工作流，打开画布右上角工作流菜单，选择 **Import from File**，选中 `n8n-video-starter.json`。成功导入后应看到 16 个节点，起点为“01 手动开始”；暂不执行。
2. 打开“05 创建视频（仅一次）”。Authentication 应为 **Generic Credential Type**，Generic Auth Type 为 **Header Auth**。在凭据下拉框选择 **Create New Credential**，取名例如 `H3 API`。
3. 在凭据里填写 **Name = Authorization**，**Value = Bearer 用户自己的Key**，即 `Bearer` 后一个空格，再接自己的 Key。这里只说明格式，没有可用 Key。保存凭据；不要把 Key 填入“02 参数设置”、HTTP 手写 Headers、URL、Code 或工作流备注。
4. 再打开“11 查询任务（同一凭据）”，选择刚才创建的**同一个 Header Auth 凭据**。模板两个 `credentials` 均留空，导入后需要分别选择；工作流无法替用户确认两个选择是否一致。
5. 打开“02 参数设置（不填 Key）”，只修改下表中的非机密参数。确认后再点击画布的 **Execute Workflow**。每次从起点执行都会新建一次任务，真实执行可能产生费用；此交付没有进行该操作。

若实例限制 Code 节点、凭据访问或不支持上述节点版本，应先解决实例兼容问题，不能通过把 Key 改写到共享节点来绕过。以后分享重新导出的 JSON 时，清理凭据名称/ID、执行样本、固定数据和可能敏感的提示词；模板原件没有任何用户凭据。

## 参数说明

| 参数 | 默认值 | 本模板接受的范围与用途 |
| --- | --- | --- |
| `model` | `h3` | 仅接受 `h3`，其他视频型号须使用各自契约 |
| `prompt` | 蓝色纸船的简短画面描述 | 去掉首尾空白后 1–4000 个 JavaScript 字符单位 |
| `duration` | `6` | 1–15 的整数，提交的请求时长，单位秒 |
| `poll_interval_seconds` | `5` | 1–30 的整数，每轮查询前等待秒数 |
| `max_polls` | `120` | 1–120 的整数，最多发送的查询 GET 次数 |
| `max_seconds` | `600` | 1–600 的整数，从参数校验通过开始计时，包含创建、等待和查询 |

数字字段保持 Number 类型，不加引号。只向创建接口发送 `model`、`prompt`、`duration`；查询参数不会进入创建请求。模板未默认发送 `resolution`、`aspect_ratio`，本地视频契约中的价格档不能当作实际出片规格保证；本轮也未验证 H3 真实时长、计费或画质。

## 执行顺序与停止条件

手动开始 → 集中设置/校验 → 创建一次 POST → 提取 task_id → 等待 → 限额检查 → GET 查询 → 判断状态 → 成功输出或停止输出。只有查询循环会返回等待节点，任何分支都不能返回创建节点。

- 创建固定请求 `POST https://xcmapi.org/v1/videos`，查询固定请求 `GET https://xcmapi.org/v1/videos/{task_id}`。两者均关闭自动重试和重定向，没有分页。
- task_id 从响应顶层或 `data` 内的 `task_id`、`id`、`request_id` 提取，优先 task_id。只接受以字母/数字开头、后续为字母/数字/下划线/横线、最长 200 字符的 ID；不接受 URL、路径或查询串。
- 响应中的 `polling_url`、`status_url`、`poll_url` 一律不作为请求目标。HTTP 请求始终使用固定本站 origin，避免向外部轮询地址发送凭据。
- `done/completed/succeeded/success` 进入成功；`failed/error/expired/cancelled/canceled` 立即停止。未知状态、响应 ID 不一致、HTTP/网络错误也停止，保留原 task_id。
- 达到次数上限或时间上限即停止；最多 120 次查询、最多 600 秒，二者以先到者为准，较小自定义值生效。查询前后均检查时间，并约预留 1 秒用于输出；实际可能少于 120 次。
- 创建请求超时或没有有效 ID 时，服务端可能已经受理。先核查控制台任务/账单，不能直接重新执行创建。停止本地查询不等于取消服务端任务，也不保证停止收费。

工作流还设置 `executionTimeout=600`。实例自己的超时限制可能更短；强制超时、手动停止或进程终止可能来不及执行最终整理节点。正常执行时应在“06 保存任务 ID”出现后及时复制 ID；最终节点未运行时，也可从本次“06”或“09 查询前检查上限”的现有输出查找。模板关闭成功、失败、手动执行数据及执行进度保存，不承诺刷新页面或重启后恢复任务。

## 查看结果与错误

“15 完成（手动下载）”输出 `ok=true`、`task_id`、`poll_count`、`content_url`、可选的 `result_url`；并明确标记 `download_status=not_downloaded`、`file_saved=false`。成功仅表示服务端报告生成完成，**没有下载或保存本地视频文件**。

“16 停止（保留 task_id）”输出 `ok=false`、`error_code`、`task_id`、`message` 和下一步。校验失败或创建未返回有效 ID 时 `task_id` 可以为 null，`task_id_display` 会说明原因。常见代码：`INVALID_SETTINGS`、`CREATE_RESULT_UNKNOWN`、`MISSING_TASK_ID`、`QUERY_HTTP_ERROR`、`POLL_LIMIT`、`TIME_LIMIT`。

停止通过普通 Code 输出实现，因此 n8n 本身可能显示绿色“执行完成”；请以最终 JSON 的 `ok` 和 `generation_status` 判断视频结果。拿到 task_id 后排查问题时，只单独 GET 查询原任务，不从“01”或“05”重跑。

## 安全手动下载

1. 先复制 `task_id`。如果有可信的外部 HTTPS `result_url`，在普通浏览器中打开并下载；**不附加本站 Authorization**。链接可能过期，且应按临时私密地址处理。HTTPS 格式校验不等于认可任意来源的内容，确认域名后再打开。
2. 若没有可用的直链，使用输出中的固定本站 `content_url`：`https://xcmapi.org/v1/videos/{task_id}/content`。在独立的手动工作流里配置一个 HTTP Request GET，选择与创建相同的 Header Auth 凭据；**不要连接回原工作流的创建节点**。URL 必须保持上述本站路径，不接受返回的外部 URL 替换。
3. 此手动请求关闭 **Follow Redirects** 和 **Send Credentials on Cross Origin Redirect**。打开 **Include Response Headers and Status**、**Never Error**；Response Format 设为 **File**，Put Output in Field 设为 `data`。先检查返回的状态和 Content-Type；只有 2xx 且确认是视频文件（或已确认的二进制文件）后，才在 Binary 输出中使用 Download 保存。
4. 若返回 30x 的 Location 或 JSON 内的外部下载地址，不要把它接到含 Header Auth 的节点继续请求，也不要把 JSON/错误体当成 MP4 保存。确认目标后用普通浏览器，或另建 **Authentication=None、无 Authorization Header** 的请求下载；必要时将本站请求改成 JSON 响应格式查看地址。Key 不能放在下载 URL 或查询参数中。

模板故意没有自动下载节点；只有实际收到完整文件并保存后，才算下载完成。上述步骤是留给使用者的手动操作，本轮未执行任何真实下载。
